# S10 설계안 — 도감·업적(B1) + 난이도(B2)

> 상태: **승인 (2026-11-18)** — Q1 서버 플레이어 기록, Q2 **현실을 더 가혹하게(신중 봇 실패 40~55%)**, Q3 보상 없음, Q4 6분류 + 업적.
> 근거: `PROGRESS.md` 로드맵 Phase 3, DEVELOPMENT_PLAN §4.2(비활성 특성은 수집률 제외)·§11.3, S9 별명.

## 0. 문제와 목표

| 문제 | 지금 | 목표 |
|---|---|---|
| 판이 끝나면 남는 게 없다 | 새 게임마다 새 게스트 신분. 지난 판의 별명·엔딩은 다시 볼 수 없음 | 여러 판에 걸쳐 쌓이는 **도감**과 **업적** |
| 다음 판을 할 이유가 약하다 | 엔딩 화면에서 끝 | "아직 못 본 엔딩 3개, 별명 17/25" 같은 **다음 목표** |
| 난이도가 하나 | 신중하게 하면 50세 전 실패 14.5% | 처음 하는 사람용 **쉬움**, 지금의 **보통**, 숙련자용 **현실** |

## 1. 플레이어 기록 (여러 판을 잇는 신분)

- 처음 게임을 만들 때 서버가 **플레이어 토큰**을 하나 더 발급하고, 브라우저는 이를 따로 보관한다(판 세션과 별개).
  이후 새 게임은 이 토큰을 함께 보내 같은 플레이어로 묶인다.
- 서버에 `players/<playerId>.json`: 도감·업적·누적 통계. 판이 **엔딩으로 확정될 때 서버가 직접** 기록한다 (클라이언트가 보내는 값은 믿지 않음).
- 같은 판은 한 번만 반영한다(runId 기록). 플레이테스트 도구로 조작한 판은 반영하지 않는다.
- 로그인·계정은 없다(제외 범위 유지). 브라우저 데이터를 지우면 도감도 처음부터. → 화면에 한 줄 안내.
- 옛 판(이 기능 전에 끝난 판)은 소급하지 않는다.

## 2. 도감 (B1)

처음 화면에 **📔 도감** 버튼. 탭 6개, 발견한 것은 이름·설명·처음 본 날·횟수, 못 본 것은 `???` + 한 줄 힌트.

| 탭 | 항목 수 | 발견 조건 | 못 본 항목 힌트 예 |
|---|---|---|---|
| 별명 | 26 | 엔딩에서 받은 대표·보조 별명 (기본 별명 포함) | "이직 한 번 없이…" |
| 엔딩 | 12 | 엔딩 종류 (실패 9 + 조기 은퇴·정년·임원) | "몸이 먼저 무너지면…" |
| 인생 목표 | 6 | **달성**한 목표 (선택만 한 것은 회색) | 목표 설명 그대로 |
| 회사 | 16 | 입사·이직으로 다녀 본 회사 | 등급과 업종만 |
| 연재 결말 | 16 | 연재 4편의 결말(마지막 화 선택 + 정리 화) | "라이벌 동기 · 결말 3개" |
| 특성 | 5 | 얻은 능력·생긴 상처 (활성 특성만, §4.2) | 능력/상처 구분만 |

- 상단에 **수집률**(예: 47/81, 58%)과 탭별 진행 막대.
- 별명은 받은 **가장 높은 난이도**를 함께 표시 (예: `현실`에서 받은 원클럽맨).

## 3. 업적 (B1)

여러 판의 누적 기록으로 달성. 보상은 없음(Q3). 엔딩 화면에 **"🏅 업적 달성!"** 띠로 알리고 도감 '업적' 탭에 모은다.

| 업적 | 조건 |
|---|---|
| 첫 출근 | 첫 판을 끝까지 |
| 열 번의 인생 | 10판 완료 |
| 버텼다 | 처음으로 50세 이상 정상 엔딩 |
| 정년 퇴임식 | 처음으로 60세 정년 |
| 별을 달다 | 임원 엔딩 |
| 현실의 생존자 | **현실** 난이도에서 정상 엔딩 |
| 현실의 별 | **현실** 난이도에서 임원 엔딩 |
| 별명 수집가 | 별명 10종 |
| 별명 박사 | 별명 20종 |
| 전설 | 전설 별명 획득 |
| 이야기꾼 | 연재 4편 모두 한 번 이상 완결 |
| 갈림길 | 한 연재의 결말을 3가지 이상 |
| 회사 투어 | 회사 8곳 경험 |
| 꿈의 직장 | S등급 회사 입사 |
| 실패도 경험 | 실패 엔딩 5종 |
| 인생 목표 마스터 | 인생 목표 6종 모두 달성 |

## 4. 난이도 (B2)

이름·성별 입력 화면에서 고른다 (기본 **보통**). 판 생성 때 고정, 사원증에 작은 표시(쉬움/현실만).

| 손잡이 | 쉬움 | 보통 | 현실 |
|---|---|---|---|
| 선택지 성공 확률 | +8%p | 0 | −5%p |
| 사건으로 잃는 체력·정신력·집중력·평판 | ×0.8 | ×1 | ×1.15 |
| 생활비 | ×0.9 | ×1 | ×1.1 |
| 시작 현금 | +500만 | 0 | 0 |
| 50세 전 실직 = 실패, 확률 비공개 | 동일 | 동일 | 동일 |

- 위험도 표시(낮음/보통/높음)는 난이도가 반영된 확률로 정한다.
- 시뮬레이션 목표 (신중 봇, 50세 전 실패): 쉬움 **3~8%**, 보통 **10~25%**(현행 14.5%), 현실 **40~55%** (Q2 결정). 현실 수치는 표보다 세게 시작해 시뮬레이션으로 맞춘다.
- 수치는 `rules.json`의 `difficulty`에 두어 시뮬레이션으로 조정한다.

## 4.5 구현 결과 (2026-11-18)

- 시뮬레이션 1,000판 (50세 전 실패율, 신중 / 무작위 봇):
  쉬움 **4.4%** / 16.3% · 보통 **14.5%** / 29.8% (변화 없음) · 현실 **46.4%** / 60.8% — 세 난이도 모두 목표 안.
- 확정 수치 (`rules.json` `difficulty`) — 설계 표보다 **훨씬 작은 값**으로 맞았다. 게임이 이미 '버티기' 경계에 있어 작은 차이도 실패율을 크게 바꾼다.

  | 손잡이 | 쉬움 | 보통 | 현실 |
  |---|---|---|---|
  | 성공 확률 | +4%p | 0 | −2%p |
  | 사건 자원 손실 | ×0.95 | ×1 | ×1.1 |
  | 생활비 | ×0.95 | ×1 | ×1.1 |
  | 시작 현금 | +300만 | 0 | 0 |

  (처음 넣은 현실 −10%p·×1.3·×1.15는 신중 봇 97% 실패, 쉬움 +8%p는 0.2% 실패였다.)
- 설계와 다른 점
  - 별명 칸은 **26개**(기본 별명 포함) → 도감 전체 81칸.
  - 못 본 항목 힌트는 새 문구 없이 기존 문구 앞부분(별명 이유·엔딩 문장 9~10자 + '…'), 회사는 등급·업종, 연재 결말은 연재 이름으로.
  - 인생 목표는 고를 때 이미 공개되므로 이름은 보이고 '달성'만 수집으로 친다.
  - 회사 수집은 '팀이 만들어진 회사'(입사·이직) 기준.
  - 플레이어 토큰은 `플레이어ID.비밀` 형식, 서버는 해시만 저장. 위조·없는 토큰이면 새 플레이어. 토큰 없이 도감을 조회하면 빈 도감.
  - 엔딩 확정 직후 같은 요청 안에서 도감에 반영하고, 엔딩 화면이 `?run=`으로 이번 판의 새 발견을 가져간다. 반영 실패는 게임 진행을 막지 않고 로그만 남긴다.
- 개발 중 주의: OneDrive 폴더에서 파일을 빠르게 연달아 고치면 개발 서버(vite)가 변경을 놓쳐 옛 코드를 내려준다. 이상하면 파일을 다시 저장(touch)하거나 서버를 재시작.

## 5. 데이터·엔진·API 변경 요약

| 위치 | 변경 |
|---|---|
| `state-schema` | `difficulty: 'EASY' \| 'NORMAL' \| 'REAL'`, `playerId: string \| null` (옛 세이브 → NORMAL / null) |
| `rules.json` | `difficulty` 손잡이 3단계 |
| 엔진 | 확률 계산·자원 손실·생활비·시작 현금에 난이도 적용, `collectRun(state)` → 이번 판 발견 목록(순수 함수), `judgeAchievements(collection)` |

| API | `POST /api/runs`에 플레이어 토큰·난이도, `GET /api/player`(도감·업적), 엔딩 확정 시 플레이어 기록 갱신, 새 업적을 엔딩 응답에 포함 |
| 저장소 | `players/` (JSON, 나중에 PostgreSQL로 교체할 인터페이스 유지) |
| 화면 | 처음 화면 '도감' 버튼, 도감 화면(탭 7: 6 + 업적), 프로필 입력에 난이도, 엔딩 화면 '새로 발견'·'업적 달성' 표시 |
| 시뮬레이션 | 난이도별 실패율·정상 엔딩 비율 리포트 |

## 6. 결정이 필요한 질문

- **Q1. 도감을 어디에 저장할까?** 추천: 서버에 플레이어 기록(엔딩 확정 시 서버가 판정, 조작 불가). 대안: 브라우저에만 저장(가장 단순, 쉽게 고칠 수 있음).
- **Q2. 난이도 차이 크기?** 추천: §4 표 (쉬움 실패 3~8%, 현실 25~40%). 대안: 현실을 더 가혹하게(실패 40~55%).
- **Q3. 업적 보상?** 추천: 없음 — 도감 수집률·배지만 (보상은 나중에 B3 대물림에서). 대안: 업적마다 다음 판 작은 혜택.
- **Q4. 도감 범위?** 추천: 6분류(별명·엔딩·인생 목표·회사·연재 결말·특성) + 업적. 대안: 별명·엔딩·업적만 먼저.
