## 실행

```bash
npm run dev          # API + 웹 (http://localhost:5173)
npm run playtest     # 플레이테스트 도구 켠 상태로 실행 (개발 전용)
npm run playtest:lan # 같은 와이파이의 휴대폰에서 접속 (docs/DEVICE_CHECK.md)
npm test             # 전체 테스트 (현재 225개)
npm run simulate -- 1000   # 자동 플레이 밸런스 리포트 (+ 난이도 요약, 상세는 -- 1000 REAL)
npm run validate:content   # 콘텐츠 검증
```

## S13 이어서 할 일 (2026-11-20~)

1. `npm run simulate -- 1000`으로 쉬움·현실 난이도 요약을 다시 잰다 (목표 3~8% / 10~25% / 40~55%). 신중 봇 보통 13.2%는 목표 하단 가까이라 쉬움이 3% 밑으로 내려갔을 수 있다
2. **사용자 결정 필요 — 부장 도달률 하락**: 신중 봇 정상 엔딩 중 부장 13.9% (목표 25~40%). S11의 '퇴근 후 노력' 평가 가산이 사라진 영향(S11 때 38.5%). 승진 규칙을 손볼지, 목표를 낮출지 물어볼 것
3. 무작위 봇 실패 15.1% (목표 30~40%) — S11 때는 무작위 야근·부업 번아웃이 실패를 키웠다. 무작위 봇 목표를 다시 정할지 함께 물어볼 것
4. 별명 획득률: 무작위 봇 10~17%로 목표대, 신중 봇은 주경야독 62%·철인 회사원 44%·마당발·N잡러 0% (봇이 늘 기댓값 높은 선택만 함). 사람 플레이로 다시 볼 것
5. 설계 문서 `DESIGN_S13_JOB_BALANCE.md` §7 구현 결과 마무리 → 화면 직접 확인(`npm run playtest`) → 커밋·푸시 → 검수 요청 (`PLAYTEST.md` B10)
- 분석용 임시 스크립트(직무별 평판 출처, 별명 선택 횟수 분포)는 저장소에 넣지 않았다. 필요하면 `autoPlay(..., onFinish)`로 다시 만든다

## 알아둘 것

- 진행 방식: 설계안 → 사용자 결정(질문) → 엔진·콘텐츠·테스트 → 화면 → 시뮬레이션 확인 → 커밋·푸시 → 검수 요청
- 정년 완주·워라밸 목표는 신중 봇에게만 쉬움(70%대). S11 이후 빚 없는 인생·내 집 마련도 60~74%. 사람 플레이 데이터로 다시 볼 것
- 난이도 목표는 신중 봇 기준(S13부터 봇은 신중·무작위 둘뿐). 보통 난이도도 성공 확률 −3%p 보정이 있다
- 정확한 확률은 화면에 공개하지 않는다(위험도만). 플레이테스트 도구는 운영 환경에서 켜지지 않는다
- 제외 범위: 창업·투자·플레이어 결혼·AI 사건·결제·앱스토어
