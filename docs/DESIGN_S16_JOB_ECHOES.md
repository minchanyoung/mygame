## 0. 문제

- 직무 단발 사건 20개는 대부분 그 자리에서 결과가 나고 끝난다. 나중에 돌아오는 것은 개발 '임시 패치' → `evt_tech_debt_return`, 기획 '숫자 부풀리기' → `evt_numbers_audit` 두 개뿐이다.
- 그래서 지름길(조용히 맞추기·할인 약속·KPI 낮추기·덮기)과 정공법의 차이는 "이번 판정 확률"뿐이고, 결과는 운이 정한다.
- S13의 알려진 문제: 현실 난이도에서 무작위 봇(27.5%)이 신중 봇(41.6%)보다 덜 실패한다. 근시안 플레이가 손해라는 것을 게임이 플레이어에게 **보여 주지** 못한다.

## 3. 엔진

- 연결은 콘텐츠만으로: 원인 선택지의 `conditionalEffects` (`on: SUCCESS | ALWAYS`, `when.flagsNone: echo_*`) → `SCHEDULE_EVENT` + 임시 플래그 24개월.
- 예약 ID를 `occurrenceId_s{지금까지 예약 수}`로 바꿨다. 확정·판정·조건부 효과가 따로 적용될 때 번호가 겹치던 잠재 버그.
- 예약 → 사건 선정 → 활성 사건 → 사건 기록으로 `sourceOccurrenceId`(선택 필드, 옛 세이브는 없음)를 넘긴다.
- `echoSource()` (`echo.ts`): 원인 사건 제목·선택지·턴. 연재 다음 화는 제외(연재 표시가 따로 있음). 감사실 메일처럼 연재 결말이 예약한 단발 사건은 포함.
- 화면 `PublicActiveEvent.echo` = { 몇 달 전, 사건 제목, 고른 답 }. 메신저·일상 카드 둘 다 답장 인용 모양.
- 연대기 항목 `ECHO` (↩, 무게 52): 「너무 쉬웠던 KPI」 ← 31세에 고른 '확실히 달성할 수 있게 낮게 잡는다'. 같은 사건의 '⚡ 위기' 줄은 빼서 한 번만 적는다.
- 노련 봇은 예약될 후속 사건을 기억한다: 후속 사건의 가장 나은 선택 기댓값 × 0.7. 신중 봇(난이도 기준)은 그대로 근시안이다.

## 4. 결정 (추천안으로 정함)

- 후속 사건은 직무당 3개 (보상 2 · 대가 1). 기존 2개(기술 부채·숫자 감사)는 그대로.
- 같은 후속은 24개월에 한 번. 지름길을 2년 안에 또 고르면 두 번째는 공짜다 — 플레이어는 이것을 모르고, 반복 사건이 더 지루하다.
- 결과 화면의 기존 안내('이 선택은 몇 달 뒤 다시 돌아올 것 같다.')는 보상·대가 구분 없이 그대로 둔다. 좋은 일인지 나쁜 일인지는 돌아올 때 안다.
